Sprint carry-over map

Carry-over is work a team commits to in a sprint but doesn't finish, so it rolls into the next one. A little is normal. A lot means plans that don't hold and less room for new work every sprint. This map shows how much carry-over there is, and where it comes from.

Every item you load is drawn across the sprint calendar. Cycle time is counted in sprints touched: an item done in the sprint it started scores 1. Hatched segments are sprints the item was carried into.

Download the sample CSV
Which columns?
  • id, title, type, category, start sprint, end sprint, status, in any order. The sample CSV shows the format.
  • Common export names work too: Work Item Type, Issue Type, Area Path, Component, State, Iteration Path, and Jira's repeated Sprint columns (first and last sprint are used).
  • Done, Closed, Resolved and similar count as done. Removed or cancelled items are left out. Open items run to the latest sprint in the file.
